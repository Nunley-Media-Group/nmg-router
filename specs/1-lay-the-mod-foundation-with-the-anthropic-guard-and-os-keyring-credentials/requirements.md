# Requirements: Lay the mod foundation with the Anthropic guard and OS keyring credentials

**Issue**: #1
**Date**: 2026-10-24
**Status**: Approved
**Author**: Rich Nunley

## User Story

**As a** developer who routes Claude Code sessions to non-Claude models
**I want** a mod scaffold that refuses Anthropic answers on the routed path and keeps provider credentials in my OS keyring, or in an encrypted vault where no keyring exists
**So that** a routed request is never answered by an Anthropic model and no credential is exposed in plain text

## Background

nmg-router is a Claude Code function-hooks mod. It answers `turn.step` requests for non-Claude models through the user's own provider plans, while Claude models go straight to Anthropic through Claude Code on the user's own login. The mod reaches providers itself, with no oh-my-pi or other runtime install, and it never reads, stores or forwards Claude credentials.

During a spike, an `opencode-go` request came back answered by `anthropic/claude-opus-5-5`, because the provider layer held an Anthropic login and silent fallback chains. The mod has no Anthropic provider. Relay providers such as ClinePass or OpenCode Go could still serve or report a Claude model, so the routed path guards both the request and the response.

The mods API has no secret store, and `$.store`, settings, logs and fixtures must never hold a credential. macOS Keychain, Windows Credential Manager and the Linux Secret Service hold credentials where they are present. Where none is found, credentials go into an AES-256-GCM vault file whose random key sits in a separate owner-only key file.

Claude Code 2.1.310 lays mod type declarations into `.claude-plugin/types/` only when an interactive session loads the folder; no CLI command writes them.

The repository has README, LICENSE, CLAUDE.md, steering, a `.gitignore` that excludes key/env/auth/token files, and `VERSION` at `0.1.0`. It has no `package.json`, plugin manifest, hooks, tsconfig, tests or CI secret scan.

## Acceptance Criteria

### AC1: Clean checkout type-checks and tests

**Given** a clean checkout on a macOS or Linux machine with Claude Code installed and the repository folder trusted
**When** the developer runs `npm run types:sync`, then `npm run typecheck` and `npm test`
**Then** `.claude-plugin/types/` is regenerated by the installed Claude Code (its `claude-code/index.d.ts` first line names the installed `claude --version`), stays untracked by git, and both commands pass

### AC2: Manifests mirror VERSION

**Given** `VERSION` contains `0.1.0`
**When** `package.json` and `.claude-plugin/plugin.json` are read
**Then** both declare version `0.1.0`, `hooks/hooks.json` lists `./register.ts`, and `claude plugin validate .` passes

### AC3: Anthropic request refused

**Given** a routed request whose provider is `anthropic`, whose base URL is an Anthropic host, or whose model id names an Anthropic or Claude model (for example `clinepass/claude-sonnet-5-5`)
**When** the guarded send checks it
**Then** it is refused with an error naming the model, and the transport, `$.http` and `$.process` fakes record zero calls

### AC4: Spike fallback reproduced and blocked

**Given** a faked provider transport that answers a request for `opencode-go/kimi-k3.1-pro` with a response whose `model` is `anthropic/claude-opus-5-5`
**When** the guarded send checks the response
**Then** it rejects with an error naming the requested and returned models, returns none of the response content, and the transport records exactly one call

### AC5: No Anthropic provider

**Given** the provider registry
**When** a provider with id `anthropic`, or with a base URL on `anthropic.com`, `claude.ai` or `claude.com` or one of their subdomains, is registered
**Then** registration is rejected and the registry does not list it

### AC6: Credentials in each OS keyring

**Given** a faked `$.process` and `$.env` for each of macOS, Windows and Linux with a working keyring
**When** the credential store saves, reads and deletes a credential for `opencode-go`
**Then** each operation calls that platform's keyring tool (`security`, `powershell.exe`, `secret-tool`) with service `nmg-router` and account `opencode-go/<account>`, the read returns the saved value, the delete removes it, and the secret never appears in any child argv or env

### AC7: No keyring uses the encrypted vault; keyring failures are refused

**Given** a platform where no supported keyring is found
**When** a credential is saved and then read
**Then** it is written as AES-256-GCM ciphertext to `vault.json` in the per-user `nmg-router` data directory, keyed by a random 256-bit key in `vault.key` beside it, with the directory created owner-only (0700) before any write and both files set to 0600 on POSIX; the read returns the saved value; and neither file contains the plaintext secret

**And given** a keyring tool that fails or reports a locked keyring
**When** a save or read runs
**Then** it is refused with a typed error naming the platform and provider (never the secret or the tool's stderr), with no vault fallback, and nothing is written to any file, `$.store` or settings

### AC8: Anthropic never stored

**Given** a save request for provider id `anthropic`
**When** the store receives it
**Then** it is refused, and no keyring tool runs and no vault file is touched

### AC9: Hygiene checks

**Given** the repository
**When** the test suite runs
**Then** a test asserts `.github/workflows/gitleaks.yml` triggers on every `push` and `pull_request` and runs gitleaks; a sentinel secret passed through the store never appears in `$.ui` output, `$.telemetry`, console logs, `$.store`, settings, error messages, vault files or child argv/env; and a fixture test fails on any token-, key- or account-id-shaped value under `tests/fixtures/`

### AC10: README explains how to keep credentials secure

**Given** the repository README
**When** a user reads its "Credential security" section
**Then** it names where credentials are kept on macOS, Windows and Linux, says when the encrypted vault is used and that its key file protects it only as far as file permissions do, gives the vault directory per OS, and tells the user to keep the directory owner-only, exclude `vault.key` from backups and sync, use full-disk encryption, install a Secret Service keyring on Linux to avoid the vault, and delete the vault directory to remove all stored credentials

## Functional Requirements

| ID | Requirement | Priority |
|----|-------------|----------|
| FR1 | Scaffold `package.json` (`typecheck`, `test`, `types:sync` scripts), `.claude-plugin/plugin.json`, `hooks/hooks.json` → `hooks/register.ts`, `tsconfig.json` extending `.claude-plugin/types/tsconfig.json`, and `vitest.config.ts` | Must |
| FR2 | `scripts/sync-mod-types.mjs` regenerates the gitignored `.claude-plugin/types/` by starting the installed Claude Code on the repo folder in a pseudo-terminal, with that path added to `.gitignore` | Must |
| FR3 | Manifest versions equal `VERSION` (`0.1.0`) | Must |
| FR4 | Pure request and response guards plus a guarded send that refuse or fail closed on Anthropic and Claude models, with no retry and no fallback | Must |
| FR5 | A provider registry that rejects Anthropic ids and hosts | Must |
| FR6 | A credential store (save, read, delete, list by provider and account) backed by macOS Keychain, Windows Credential Manager and Linux Secret Service, with secrets only on stdin | Must |
| FR7 | An AES-256-GCM keyfile vault used only when no supported keyring is found; typed errors for keyring failures; no plain-text storage and no Anthropic credentials | Must |
| FR8 | A gitleaks workflow, a reusable sentinel-leak test harness over the `$` fakes, and a fixture hygiene test | Must |
| FR9 | Tests fake `$.http`, `$.process`, `$.env`, `$.fs`, `$.session`, `$.store`, `$.ui` and `$.telemetry`, and never contact a real provider | Must |
| FR10 | README "Credential security" section covering storage per OS, the vault's protection level and hardening steps | Must |

## Out of Scope

- Provider definitions, login UI and routing of model steps
- Rotating credentials across accounts
- Migrating vault entries into a keyring that appears later
